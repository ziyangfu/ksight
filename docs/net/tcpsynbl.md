# tcpsynbl 诊断指南

## 概述

`tcpsynbl` 用于监控 TCP SYN Backlog 队列（半连接队列）的负荷情况。它通过直方图展示队列深度的分布，帮助识别服务器在处理高频并发请求时的瓶颈。

**核心场景**：

1. **半连接队列溢出**：大量 SYN 包到达但三步握手未完成，导致内核丢弃新请求。
2. **SYN Flood 攻击识别**：识别异常的半连接激增。
3. **系统调优参考**：为调整 `net.ipv4.tcp_max_syn_backlog` 提供实测数据支持。

## 命令行参数

| 参数 | 缩写 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `--timestamp` | `-T` | bool | false | 在输出中包含时间戳 |
| `--ipv4`      | `-4` | bool | false | 仅追踪 IPv4 |
| `--ipv6`      | `-6` | bool | false | 仅追踪 IPv6 |
| `--verbose`   | -    | bool | false | 打印调试详细信息 |
| `interval`    | -    | int  | 99999999 | 打印时间间隔（秒） |
| `count`       | -    | int  | 99999999 | 打印次数 |

## AI 逻辑与调用指引

### 何时调用

AI Agent 在观测到以下现象时，应考虑调用此工具：

- **连接被重置 (Connection Reset)**：客户端反馈连接请求被拒绝，但服务器主进程运行正常。
- **建连成功率下降**: 丢包率不高，但连接建立的成功率却显著抖动。
- **内核溢出报警**: `dmesg` 出现 `Possible SYN flooding on port ...` 信息。

### 输出解读 (AI 视角)

- **直方图分布**: 关注直方图右侧的高数值区间。如果大量采样落入 512 或 1024 以上的区间，说明半连接队列极度拥挤。
- **溢出判定**: 长期处于高位负荷通常预示着新连接将被内核丢弃（Drop），AI 应建议增大队列长度或排查应用层处理挂起问题。

## 与相关工具的关系

- **与 tcptracer 的联动**: 若 `tcptracer` 显示 `Accept` 事件显著少于 `Connect` 请求，应启动 `tcpsynbl` 检查是否卡在半连接阶段。
- **与 tcpconnlat 的联动**: 如果建连延迟（从 SYN 到 SYN-ACK）偶尔极大，可能是因为请求正在 SYN 队列中排队。
