# tcptracer 诊断指南

## 概述

`tcptracer` 为内核级的 TCP 连接建立（Connect）、监听接收（Accept）以及连接断开（Close）提供全生命周期的事件记录。它勾勒了系统中所有网络活动的拓扑快照。

**核心场景**：

1. **短连接风暴审计**：识别是否存在高频的 `Connect` + `Close` 循环，导致资源枯竭。
2. **异常外连探测**：记录是否有非期望的进程发起出站连接（可疑连接证据）。
3. **连接流转审计**：为多微服务环境提供进程级别的交互行为日志。

## 命令行参数

| 参数 | 缩写 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `--timestamp` | `-t` | bool | false | 在输出中包含时间戳 |
| `--print-uid` | `-U` | bool | false | 在输出中包含用户 UID |
| `--pid`       | `-p` | uint32 | 0 | 仅追踪指定 PID 的连接活动 |
| `--uid`       | `-u` | uint32 | -1 | 仅追踪指定 UID 的连接活动 |
| `--verbose`   | -    | bool | false | 打印调试详细信息 |

## AI 逻辑与调用指引

### 何时调用

AI Agent 在观测到以下信号时，应考虑调用此工具：

- **文件描述符 (FD) 泄露**: `proc/pid/fd` 数目快速增长，AI 需要通过 `tcptracer` 确认是哪些连接只有创建没有及时关闭。
- **服务发现异常**: 后端节点不断变换地址，AI 需提取稳定的建连记录进行分析。
- **应用上线波动评估**: 新版本发布后，对比连接创建频率及其成功率。

### 输出解读 (AI 视角)

- **TYPE (C/A/X)**: **C (Connect)** 为主动发起的出站连接；**A (Accept)** 为接收到的进站请求；**X (Close)** 为连接关闭（包含各种原因的断开）。
- **SADDR/DADDR**: 连接的起始点和终点，是分析服务拓扑的主键。

## 与相关工具的关系

- **作为诊断起点**: 通常作为第一个全局观测工具，确定“谁在连谁”，随后引导 AI 调用更具体的工具（如 `tcpretrans` 或 `tcpconnlat`）去分析具体的连接稳定性。
- **与 sofdsnoop 的联动**: 如果 `tcptracer` 观察到 Socket 的 `Accept` 但之后没有看到 `Close`，AI 可结合 `sofdsnoop` 查看该 FD 是否被传递给了其他 Worker 进程。
