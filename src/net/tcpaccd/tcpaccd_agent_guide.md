# tcpaccd 诊断与治理指南

## 概述

`tcpaccd` (TCP Accelerated Daemon) 是一个利用 eBPF 技术实现本地 TCP 通信透明加速的工具。它通过 bypass（绕过）内核协议栈的机制，让运行在同一节点上的不同进程在进行 TCP 交换时，如同直接在内存中拷贝一样高效。
> sockops是一种通过 BPF 程序拦截 socket 操作，然后动态设置 TCP 参数的机制

**核心功能**：
1. **本地通信加速**：针对回环地址（127.0.0.1）或本地网卡 IP 的 TCP 连接进行重定向优化。
2. **高性能 IPC**：将传统 TCP 通信转换为类似共享内存性能的内核级短路转发。
3. **透明增强**：无需重启应用或修改任何代码即可生效。

## 核心原理

`tcpaccd` 结合了 eBPF 的两种高级程序类型：
1. **握手感知 (`sockops`)**：在内核 `inet_listen` 和连接建立阶段，自动捕获正在进行的 TCP 握手。一旦确认连接双方都在本地，则将对应的 Socket 句柄（Sock Object）存入内核特定的 `SOCKHASH` 表中。
2. **数据捷径 (`sk_msg`)**：挂载在 Socket 的消息处理路径上。当发送方调用 `sendmsg` 时，eBPF 程序在内核中直接通过五元组查找 `SOCKHASH` 表。如果目标 Socket 存在，数据包将直接被推送到接收方的接收队列（Ingress），从而跳过 IP 封包、路由查找、校验和计算等所有协议栈开销。

## 命令行参数 (CLI Arguments)

| 参数 | 缩写 | 类型 | 说明 |
| --- | --- | --- | --- |
| `--cgroup-path` | `-c` | string | **必须参数**。指定工具监护的 cgroup 路径（例如 `/sys/fs/cgroup/`）。只有在该 cgroup 树下的进程连接行为才会被加速。 |

## AI 逻辑与调用指引

### 何时调用（治理决策）
AI Agent 应在以下场景评估并建议启动 `tcpaccd`：

1. **同机 RPC 性能瓶颈**：当微服务架构中大量 Sidecar或本地代理导致额外的网络延迟时。
2. **降低跨进程延迟**：业务对实时性要求极高（如车载系统内部组件通信），需进一步压榨传统的 TCP 通信延迟。

### 输出解读 (AI 视角)
- `tcpaccd` 本身不输出频率诊断数据，它是一个**治理型插件**。
- **效果评估**：Agent 启动该工具后，应观测系统的平均 Latency 变化以及 CPU 在协议栈处的消耗降低。

## 相关工具联动

- **与 nsp (netstack_probe) 联动**：如果 `nsp` 的 Dimension C 显示本地软中断（SoftIRQ）过载，且流量集中在回环接口，启动 `tcpaccd` 是最有效的治理手段。
- **与 tcpconnect/solisten 联动**：利用这些工具建立的拓扑视图，AI 可以自动识别哪些频繁交互的服务对适合使用 `tcpaccd` 进行加速。
- **与 tcpnagle 联动**：`tcpaccd` 的加速是结构性的。在开启本地加速后，即使 Nagle 算法开启，由于协议栈被绕过，其带来的延迟副作用也会大幅降低。

## 性能影响与局限性
- **性能改进**：通常能减少 15%~40% 的本地通信延迟，并降低相应的 CPU 软中断消耗。
- **局限性**：
    - **非跨机**：仅能加速本机的 TCP 通信。
    - **协议限制**：目前的加速逻辑主要支持标准流式 TCP（SOCK_STREAM）。如果使用了异常复杂的 TCP 选项，可能会引发回退到标准协议栈逻辑。
    - **内核依赖**：需要系统开启 `CONFIG_BPF_SYSCALL` 并支持 `sockmap` 相关特性。
