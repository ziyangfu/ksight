# tcpconnlat 诊断指南

## 概述

`tcpconnlat` 测量从发送 SYN 包到接收回 SYN-ACK 的完整往返时间（RTT），揭示了建立 TCP 连接的准备阶段（Handshake）的延迟。

**核心场景**：

1. **握手缓慢分析**：连接成功建立但第一个请求发起前存在明显停顿。
2. **CDN/负载均衡后端选择**：测量到不同物理地址或后端的建立连接真实时延。
3. **网络链路质量评价**：发现链路中的初始排队延迟。

## 命令行参数

| 参数 | 缩写 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `--timestamp` | `-t` | bool | false | 在输出中包含时间戳 |
| `--pid`       | `-p` | uint32 | 0 | 仅追踪指定 PID 的连接 |
| `--lport`     | `-L` | bool | false | 在输出中包含本地端口号 (LPORT) |
| `--verbose`   | -    | bool | false | 打印调试详细信息 |
| `delay`       | -    | double | 0.0 | 仅追踪超过此延迟（毫秒 ms）的连接 |

## AI 逻辑与调用指引

### 何时调用

AI Agent 在观测到以下指标异常时，应考虑调用此工具：

- **首字节响应时间 (TTFB) 增长**: 用户反馈响应慢，但后端处理耗时未见显著增长。
- **负载均衡异常回源**: 怀疑局部网络拥塞导致特定节点握手变慢。
- **高并发下的排队**: 探测在高并发请求时，平均建连延迟是否异常波动。

### 输出解读 (AI 视角)

- **Latency (us)**: 输出单位为微秒。如果某些连接的 Latency 显著（例如 2 倍以上）偏离该目标的基准 RTT，说明三次握手第一步在网络中发生了严重排队或拥塞。
- **ADDR/PORT**: AI 可据此汇总出哪些对端 IP 表现最差。

## 与相关工具的关系

- **与 tcptracer 的联动**: 若 `tcptracer` 捕捉到短连接风暴，AI 应随后使用 `tcpconnlat` 确认这些短连接是否因高频建连导致了竞争性延迟增长。
- **与 tcpretrans 的联动**: 建连阶段的极高延迟通常伴随着 `tcpretrans` 指示的 SYN 包重传。
