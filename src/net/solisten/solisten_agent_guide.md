# solisten 诊断与治理指南

## 概述

`solisten` 是一个内核级的 Socket 监听审计工具。它能实时捕获系统内所有进程开启服务端口的动作。在微服务架构或复杂的容器化环境中，它可以帮助 AI 建立精确的“进程-端口”映射视图，并诊断端口冲突或服务启动失败的根源。

**核心功能**：
1. **服务启动审计**：记录 `listen()` 操作的详细信息。
2. **进程识别**：精准关联开启监听动作的 PID 与进程名（Comm）。
3. **失败原因诊断**：捕获监听失败的内核错误码（如端口冲突、权限不足）。
4. **队列容量核查**：记录应用层设置的 `backlog` 大小，用于评估服务的并发承载能力。

## 核心原理

工具挂载在内核的 `inet_listen` 函数上：
1. **Entry 阶段**：在该函数被调用时，eBPF 程序通过 `struct socket` 提取其绑定的本地 IP 地址、端口以及协议族信息。同时记录应用层传入的 `backlog` 参数。这些信息通过线程 ID (TID) 作为键，暂时存储在内核 Map 中。
2. **Exit 阶段**：利用 `kretprobe` 或 `fexit` 捕获函数运行结果。程序通过 TID 找回对应的上下文，并将内核处理的返回码（0 表示成功，负数表示失败）填入事件。
3. **输出**：采集到的结构化数据包通过异步 Perf Event 缓冲区推送到用户态展示，实现非阻塞式的透明监控。

## AI 逻辑与调用指引

### 何时调用（场景决策）
AI Agent 在面临以下信号时应启动 `solisten`：

1. **服务启动异常排查**：当业务反馈“端口无法绑定”或“服务启动失败”时，AI 调用此工具获取实时的内核报错真相。
2. **影子服务检测**：用于安全合规审计。确认系统是否存在未备案的、监听在全网段（0.0.0.0）的特权端口或未知服务。
3. **抗压能力评估**：在性能调优场景下，AI 用于获取业务实际设置的 `backlog` 容量，判断是否需要在系统层面调整 `tcp_max_syn_backlog` 或应用配置。

### 输出解读 (AI 视角)
- **发现 RET = -EADDRINUSE (-98)**：表示端口冲突。AI 应主动搜索当前占用该端口的另一个进程信息。
- **发现 BACKLOG 极低**：如果该服务承载的是高频流量（由 `netstack_probe` 的带宽数据辅助判断），AI 应提示优化 `listen()` 调用参数。
- **发现非预期的 IP 绑定**：例如预想绑定的内网 IP 被绑定到了外网网卡，AI 应识别为此为配置错误导致的潜在安全风险。

## 相关工具联动

- **与 tcpaccept 联动**：`solisten` 是诊断的防御线（谁开了门），`tcpaccept` 是诊断的流水线（谁进来了）。
- **与 netstack_probe 联动**：如果 `solisten` 确认监听成功但端口扫描失败，AI 应联动 `netstack_probe` 核查协议栈拦截策略（Dimension A）及实时丢包情况（Dimension C）。
- **与 tcpconnect 联动**：合并分析，AI 可自动识别本机微服务拓扑模型。

## 性能影响与局限性
- **性能开销**：极低。由于监听动作（Listen）在常规应用生命周期中频率极低，挂载点的执行对系统性能几乎无影响。
- **可观测性范围**：覆盖所有 AF_INET / AF_INET6 协议簇。无法检测直接使用 `AF_PACKET` 或跳过标准内核协议栈（如 DPDK）的监听行为。
