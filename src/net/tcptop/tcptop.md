# tcptop 诊断指南

## 概述

`tcptop` 类似于 Linux 的 `top` 工具，但专门用于监控实时 TCP 吞吐量。它按进程和连接显示实时的发送（TX）和接收（RX）带宽，是识别网络热点进程的首选工具。

**核心场景**：

1. **带宽占用突增排查**：迅速找出当前哪个进程正在占用网卡的所有带宽。
2. **流量清洗/限流验证**：实时验证某个流是否按照预期被限速。
3. **服务流量倾斜监测**：在多负载均衡环境中，观察是否有连接获得了异常高的流量分配。

## 命令行参数

| 参数 | 缩写 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `--pid`       | `-p` | uint32 | -1 | 仅追踪指定 PID 的流量 |
| `--cgroup`    | `-c` | string | "" | 仅追踪指定 Cgroup 路径下的进程 (如 Docker 容器) |
| `--ipv4`      | `-4` | bool | false | 仅显示 IPv4 统计 |
| `--ipv6`      | `-6` | bool | false | 仅显示 IPv6 统计 |
| `--nosummary` | `-S` | bool | false | 不显示顶部的系统汇总行 |
| `--noclear`   | `-C` | bool | false | 实时更新时不清除屏幕 |
| `--sort`      | `-s` | enum | "all" | 排序维度：`all` (总流量), `sent`, `received` |
| `--rows`      | `-r` | uint32 | 20 | 显示的最大行数 |
| `--verbose`   | `-v` | bool | false | 打印调试详细信息 |
| `interval`    | -    | uint32 | 1 | 刷新时间间隔（秒） |
| `count`       | -    | uint32 | MAX | 刷新次数 |

## AI 逻辑与调用指引

### 何时调用

AI Agent 在观测到以下信号时，应考虑调用此工具：

- **网卡带宽利用率报警**: `nmon` 或 `sar` 显示网卡接近满载。
- **系统 CPU 被中断占满**: 怀疑是有进程在进行大量网络读写导致的中断风暴。
- **服务响应抖动**: 同时伴随着整体基础流量的非正常波动。

### 输出解读 (AI 视角)

- **RX_KB / TX_KB**: 重点观察最高的几个条目。超过业务基准线（如平常 1MB/s 突增到 10MB/s）的进程应被列为怀疑对象。
- **LADDR/RADDR**: 观察目标地址。如果是未知的外部 IP 或大量的短 IP 连接，AI 可能推断为受攻击或服务配置错误。

## 与相关工具的关系

- **与 tcpretrans 的联动**: 如果 `tcptop` 显示某个流带宽大但业务超时，应立即启动 `tcpretrans` 探测此流是否有严重丢包。
- **后续动作**: 一旦确认高流量 PID，AI 可进一步调用性能分析工具（如 `profiler`）定位产生网络 IO 的具体代码逻辑。
