# tcprtt 诊断指南

## 概述

`tcprtt` 用于分析 TCP 连接的往返时间（RTT）。它通过追踪内核 TCP 协议栈中维护的平滑 RTT（Smoothed RTT）数据，以直方图的形式展示网络延迟的分布情况。

**核心场景**：

1. **网络抖动诊断**：评估系统网络延迟的离散程度，识别是否存在长尾延迟（Long Tail Latency）。
2. **应用响应分析**：分析特定的进程或端口在网络传输环节消耗的时间。

## 命令行参数

| 参数 | 缩写 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `--interval`  | `-i` | uint32 | 99999999 | 打印结果的间隔时间（秒） |
| `--duration`  | `-d` | uint32 | 0 | 追踪的总时长（秒），0 表示持续追踪 |
| `--timestamp` | `-T` | bool | false | 在输出中包含时间戳 |
| `--millisecond`| `-m` | bool | false | 使用毫秒（ms）作为直方图单位（默认微秒 us） |
| `--lport`     | `-p` | uint16 | 0 | 仅统计匹配的本地端口 |
| `--rport`     | `-P` | uint16 | 0 | 仅统计匹配的远程端口 |
| `--laddr`     | `-a` | string | "" | 过滤指定的本地 IP 地址 (v4/v6) |
| `--raddr`     | `-A` | string | "" | 过滤指定的远程 IP 地址 (v4/v6) |
| `--byladdr`   | `-b` | bool | false | 按照本地地址分别统计直方图 |
| `--byraddr`   | `-B` | bool | false | 按照远程地址分别统计直方图 |
| `--extension` | `-e` | bool | false | 打印扩展汇总信息（如平均值） |
| `--verbose`   | `-v` | bool | false | 打印调试详细信息 |

## AI 逻辑与调用指引

### 何时调用

AI Agent 在观测到以下异常或需求时，应考虑调用此工具：

- **业务响应变慢**: 当应用监控显示响应时间（RT）上升，但 CPU/内存正常时，需调用 `tcprtt` 排查是否为网络延迟增加导致。
- **网络波动验证**: 在系统发布或网络变更后，AI 调用 `tcprtt` 验证网络性能是否保持稳定。

### 输出解读 (AI 视角)

- **Latency (us/ms)**: 直方图的 X 轴。AI 应重点关注落在高延迟区间（如 >100ms）的样本占比。
- **Average (需开启 -e)**: 平均 RTT。如果均值远高于基准线，说明链路质量整体下降；如果均值正常但直方图有长尾，说明存在严重抖动。
- **Count**: 样本数。AI 需结合样本数判断数据的统计学意义。

## 与相关工具的关系

- **与 tcppktlat 的关联**: `tcppktlat` 关注数据包在协议栈内部的停留时间，`tcprtt` 关注网络物理链路的往返时间。
- **诊断闭环**: 先用 `tcprtt` 确认是否为链路延迟（网速慢），若 RTT 正常但应用依然慢，再用 `tcppktlat` 排查是否为内核协议栈或 CPU 调度问题。
